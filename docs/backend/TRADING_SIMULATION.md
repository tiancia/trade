# 策略参数版本与模拟资金

本页所有管理写请求需携带 `X-Trade-CSRF: 1`，浏览器还须使用同源或配置允许的 Origin。驾驶舱自动附加该头；命令行调用也不能省略。它不替代网关认证、配置版本冲突检查或 PAPER/LIVE 门禁。

驾驶舱的策略页可以修改当前 `threshold-event` 策略实例的参数。保存产生新的配置版本，仅用于随后开始的决策；已经开始的决策继续使用取得的参数快照。配置版本及变更说明保存在 MySQL，重启不会恢复成 YAML 参数。

## 修改策略参数

1. 在策略页展开“参数与版本”，读取当前配置及版本历史。
2. 修改参数并填写变更说明，再保存。`0.02` 表示 2%，数量和金额分别使用基础币及计价币单位。
3. 保存请求携带 `expectedVersion`；其他页面先保存时返回 409，需重新读取当前版本并核对草稿。

修改参数不会自动切换活动策略，也不会取消已有订单。配置版本与“当前策略选择”的 revision 是两套不同的版本号。单笔金额上限、风控和真实下单门禁继续生效；参数中的买入金额不能绕过全局上限。

页面修改的是策略评估参数。事件扫描的唤醒阈值、扫描间隔和全局风控上限仍来自部署配置；保存参数本身不会立即执行一轮交易，下一次定时或事件决策才使用新版本。

每条新决策保存 `strategyConfigVersion` 与完整 `strategyConfigSnapshot`。模拟成交和估值记录关联策略及配置版本；旧记录不会被新参数重新标记。上线前的历史决策没有该字段时应视为旧版本未知，不补造版本。

## 开始模拟

在 PAPER 模式下，填写计价币初始资金并创建模拟批次。新批次从现金和空仓开始，旧批次的账本及历史保留。没有初始化模拟资金时不执行新的模拟成交，不从真实账户余额或旧 PAPER 持仓自动推算初始资金。

PAPER 的持仓、现金和风险状态属于模拟批次，行情仍来自公开行情接口。实盘账户余额、挂单及成交不参与模拟决策、下单额度或收益计算。

- 净值 = 可用现金 + 持仓数量 × 最近有效市场价格。
- 未实现盈亏 = 持仓市值 − 剩余持仓成本。
- 已实现盈亏 = 卖出净收入 − 本次释放的持仓成本，包含手续费影响。
- 总收益率 =（当前净值 − 初始资金）÷ 初始资金 × 100%。

买入按现有模拟规则从得到的基础币中扣手续费，买入现金计入持仓成本；卖出从计价币收入中扣手续费。余额不足和超额卖出被拒绝，不允许模拟账户透支。当前资金账本支持现货 BUY/SELL，不把合约操作伪装成现货成交。

页面显示资金曲线、估值时间及成交记录，可切换历史批次并按策略配置版本筛选。一个批次内修改参数会继续持有原仓位，因此筛选后的记录代表该版本生效期间的账户表现，包含继承仓位的价格变化，不能当作独立回测收益。需要从相同资金、空仓条件比较时，分别创建新批次；历史行情对比仍使用独立回测入口。

估值依赖最新公开价格，过期数据会标记为过期。模拟成交使用报价和设定手续费，不代表交易所实际成交、滑点、深度或未来实盘收益。

## 接口和部署

- `GET|PUT /api/trading/strategies/{strategyId}/configuration`
- `GET /api/trading/strategies/{strategyId}/configuration/history`
- `GET /api/trading/paper/account`
- `POST|GET /api/trading/paper/sessions`
- `GET /api/trading/paper/sessions/{sessionId}`
- `GET /api/trading/paper/sessions/{sessionId}/equity`
- `GET /api/trading/paper/sessions/{sessionId}/fills`

写接口沿用现有网关登录和网络隔离。创建批次携带当前批次标识及版本，防止并发页面互相覆盖；旧批次中的在途决策不能写入新批次。

完整建表语句在 [Trading schema](../../backend/src/main/resources/db/schema/trading/schema.sql)。已有库可按 [升级说明](../../backend/src/main/resources/db/upgrade/README.md) 应用对应新增表脚本。启动 schema 可以创建缺失的新表，不能替代已有表字段升级。部署需要更新后端和驾驶舱；本地离线测试不能证明生产 MySQL 锁、真实行情或实盘效果。
