# 策略参数版本与模拟资金

本页所有管理写请求需携带 `X-Trade-CSRF: 1`，浏览器还须使用同源或配置允许的 Origin。驾驶舱自动附加该头；命令行调用也不能省略。它不替代网关认证、配置版本冲突检查或 PAPER/LIVE 门禁。

驾驶舱的策略页可以修改 `threshold-event` 和 `intraday-technical` 策略实例的参数。保存产生新的配置版本；已采集但尚未预留下单的旧决策会因版本变化而跳过，等待下一轮新决策。配置版本、变更说明和活动策略选择保存在 MySQL，重启不会恢复成 YAML 参数或其他实例的本地选择。

## 修改策略参数

1. 在策略页展开“参数与版本”，读取当前配置及版本历史。
2. 修改参数并填写变更说明，再保存。`0.02` 表示 2%，数量和金额分别使用基础币及计价币单位。
3. 保存请求携带 `expectedVersion`；其他页面先保存时返回 409，需重新读取当前版本并核对草稿。

修改参数不会自动切换活动策略，也不会取消已有订单。配置版本与“当前策略选择”的 revision 是两套不同的版本号。单笔金额上限、风控和真实下单门禁继续生效；参数中的买入金额不能绕过全局上限。

手工和 AI 修改共用数据库互斥边界。同一库只要有受管理 LIVE 持仓、未决订单或当前 PAPER 会话持仓，切换策略和修改参数都返回 409，包括零碎正数持仓；不能用切换策略改变已有仓位的退出规则。预留下单和模拟成交在同一边界检查活动选择 revision 与参数版本，防止在途旧决策随后成交。全局配置 ID 跨模式共享，因此另一模式的持仓也会阻止修改。

页面修改的是策略评估参数。旧策略的事件唤醒阈值、扫描间隔和全局风控上限仍来自部署配置；保存参数本身不会立即执行一轮交易，下一次定时或事件决策才使用新版本。当前活动类型为 `intraday-technical` 时，事件扫描每分钟直接评估已收盘 15m K 线，不再要求先达到旧 1m 涨幅/放量条件；旧策略保留原调度行为。

每条新决策保存 `strategyConfigVersion` 与完整 `strategyConfigSnapshot`。模拟成交和估值记录关联策略及配置版本；旧记录不会被新参数重新标记。上线前的历史决策没有该字段时应视为旧版本未知，不补造版本。

## 15 分钟日内候选策略

已有 OKX `getCandles` / `history-candles` 公共接口和 business WebSocket 支持 15m，无需新交易接口或额外 API 权限。图表/WS 支持 1m、5m、15m、1H、4H；决策上下文显式承载 1m、5m、15m，未知周期不回退成 1m。公开周期和完成标记以 [OKX 文档](https://app.okx.com/docs-v5/en/#order-book-trading-market-data-get-candlesticks) 为准。

新实例追加在旧实例之后；部署不自动修改现有活动选择和已保存参数。三个实例共享 `intraday-technical` 类型，通过 `mode` 使用不同规则，均限定现货多头、确认收盘的 15m K 线：

| 实例 | 入场条件 | 候选止损 / 止盈 |
| --- | --- | --- |
| `intraday-trend-15m` | EMA9 > EMA21，ADX≥18，价格从EMA9下方收回，RSI上升且45–68，量比≥1 | 0.6% / 1.8% |
| `intraday-breakout-15m` | 收盘突破此前20根最高价，EMA顺势、ADX≥20，RSI50–72，量比≥1.3 | 0.6% / 1.8% |
| `intraday-range-15m` | ADX≤20，价格从布林下轨之外收回，RSI上升且20–45，量比≥0.8 | 0.4% / 1.2%，回到布林中轨也退出 |

共同指标默认 EMA9/21、Wilder RSI14/ATR14/ADX14、20根布林带（总体标准差，2倍）、20根唐奇安前高和20根历史均量。唐奇安和均量排除信号根。实时和回测均固定取末尾 `max(3×慢EMA周期, 指标最低历史需求)` 根确认 K 线计算，默认63根，避免历史长度不同导致计算口径漂移。入场与指标退出遇到时间缺口、无效 OHLCV、过期/未来 K 线或历史不足时 HOLD。已有可交易持仓的固定止损止盈独立检查最新一根有效、已收盘且新鲜的15m OHLC，不因旧指标历史缺口、成交量异常或暖机不足而跳过；最新价格本身非法、未来或过期时仍不执行。该退出的metadata带 `priceProtectionOnly=true`。`trade.trading.fifteen-minute-candle-limit` / `TRADE_TRADING_FIFTEEN_MINUTE_CANDLE_LIMIT` 默认200，允许2–300；参数预热要求不能超过采集上限减一。

新策略不追加已有可交易的受管理仓位，退出只卖受管理数量。根据当前产品的 `lotSz` 向下取整后为零或低于 `minSz` 的零碎持仓保留在账本中，允许下一根有效信号重新入场并累计这些资产，不会清零仓位或成本；未知产品规则时保守地把正数持仓视为已有仓位。ATR/价格默认须在0.15%–3%之间；趋势入场价格不能高于快EMA超过2.5个ATR。入场先从计划收益扣除双边手续费和滑点，再检查净收益空间与全局最低盈亏比。均值回归按中轨和固定目标中较近的收益空间检查。该计算是计划空间，不是胜率估计或收益保证。回测使用请求的实际费率/滑点，实时使用 `taker-fee-rate` 与策略的滑点估算；PAPER成交本身仍采用原报价成交模型。

持久化信号身份由标的、策略、方向、15m周期和信号时间组成，同根同方向不因配置、数量或1m快照变化重复下单；PAPER按模拟批次隔离。旧策略身份算法保留。上一笔成交发生于当前信号收盘时刻或之后时，新入场等待下一根收盘；`lastTradeTime` 作为成交事实随LIVE累计成交/PAPER成交在同一资金事务内保存，不依赖 `risk.enabled` 或PAPER事后风险计数回调。部分成交推进时间，重放不推进，迟到成交及旧风险快照不能回退时间。持久化订单/成交身份仍是防重依据，每根每方向最多一个身份，并不保证全局每天固定交易次数。

确定性决策仅采集当前策略所需的 K 线周期、Ticker、产品规则和执行所需的余额；不等待盘口、历史订单、历史成交或其他周期接口。日亏损、回撤和连亏冷却只阻止增加风险，不触发禁止所有下单的持久化 HALTED；人工停止、未知订单和账实异常仍保留原有门禁。

连亏按从空仓建仓到完整平仓的已实现净盈亏计数，包含分摊的买入成本、买卖费用和全部部分卖出；重放不重复计数。PAPER 现金、持仓、成交及风险事实一起提交或回滚。升级后旧的权益采样连亏及冷却在首次风险更新时重置；已有仓位不补造历史盈亏，下次从空仓建仓才开始新口径。

止损、止盈和趋势失效都在15m收盘确认后评估，继承持仓的成本作为基准，不是交易所原生止损单，也不模拟盘中精确触价成交。全局风险、资金停止、领导租约、下单幂等和LIVE双门禁继续生效。实盘选择前，先用包含费用的多段历史和后续样本外区间比较，再创建独立、空仓的PAPER批次观察。日均完成交易数只是频率评估目标，不能为凑次数取消成本、风控或确认条件。

## 开始模拟

在 PAPER 模式下，填写计价币初始资金并创建模拟批次。新批次从现金和空仓开始，旧批次的账本及历史保留。没有初始化模拟资金时不执行新的模拟成交，不从真实账户余额或旧 PAPER 持仓自动推算初始资金。

PAPER 的持仓、现金和风险状态属于模拟批次，行情仍来自公开行情接口。实盘账户余额、挂单及成交不参与模拟决策、下单额度或收益计算。

- 净值 = 可用现金 + 持仓数量 × 最近有效市场价格。
- 未实现盈亏 = 持仓市值 − 剩余持仓成本。
- 已实现盈亏 = 卖出净收入 − 本次释放的持仓成本，包含手续费影响。
- 总收益率 =（当前净值 − 初始资金）÷ 初始资金 × 100%。

买入按现有模拟规则从得到的基础币中扣手续费，买入现金计入持仓成本；卖出从计价币收入中扣手续费。余额不足和超额卖出被拒绝，不允许模拟账户透支。当前资金账本支持现货 BUY/SELL，不把合约操作伪装成现货成交。

成交、估值、风险更新和会话维护先锁定当前会话指针，再通过锁定读取取得最新账户与风险数据。即使外层事务已建立旧快照，也不能用旧现金、持仓或风险计数覆盖其他事务的新结果；数据库报告并发冲突时整笔事务回滚，等待刷新后重试。MySQL 普通快照读取与锁定读取的区别见[官方事务隔离说明](https://dev.mysql.com/doc/refman/8.4/en/innodb-transaction-isolation-levels.html)。

页面显示资金曲线、估值时间及成交记录，可切换历史批次并按策略配置版本筛选。同一批次只允许在空仓且没有未决订单时修改参数；按版本筛选仍代表该版本生效期间的账户表现，不能当作独立回测收益。需要从相同资金、空仓条件比较时，分别创建新批次；历史行情对比仍使用独立回测入口。

估值依赖最新公开价格，过期数据会标记为过期。模拟成交使用报价和设定手续费，不代表交易所实际成交、滑点、深度或未来实盘收益。

## 删除模拟会话

在总览中选择当前或历史模拟会话，点击“删除此会话”，核对会话 ID 后确认。删除会永久清除该会话及其模拟成交、资金曲线和风险状态；策略配置、回测和独立决策审计保留。当前会话被删除后不再有已初始化的模拟资金，需要新建会话才能继续模拟成交；历史会话不会自动恢复为当前会话。

删除仅允许在 PAPER 现货模式下操作，并携带所选会话的 `expectedVersion`。后端在同一事务内锁定标的的当前会话指针，与成交、估值和会话替换串行处理；已有新成交时返回 409，需重新加载后核对。旧会话的在途决策不能写入删除后新建的会话。页面超时或断网时不宣称删除成功，需重新加载确认。

## 接口和部署

- `GET|PUT /api/trading/strategies/{strategyId}/configuration`
- `GET /api/trading/strategies/{strategyId}/configuration/history`
- `GET /api/trading/paper/account`
- `POST|GET /api/trading/paper/sessions`
- `GET /api/trading/paper/sessions/{sessionId}`
- `DELETE /api/trading/paper/sessions/{sessionId}?expectedVersion=3`：成功返回 204；版本或运行模式冲突返回 409，所选标的下不存在会话返回 404。
- `GET /api/trading/paper/sessions/{sessionId}/equity`
- `GET /api/trading/paper/sessions/{sessionId}/fills`

写接口沿用现有网关登录和网络隔离。创建批次携带当前批次标识及版本，防止并发页面互相覆盖；旧批次中的在途决策不能写入新批次。

`GET /api/trading/runtime/status` 同时返回 `instId`、`baseCcy`、`quoteCcy`。驾驶舱行情查询、图表标题和回测默认标的跟随此配置，兼容旧后端缺少字段的响应；PAPER初始资金可作为回测默认资金，回测本身仍独立于当前PAPER持仓。

完整建表语句在 [Trading schema](../../backend/src/main/resources/db/schema/trading/schema.sql)。运行时结构由 Flyway 管理，本次新增字段、共享选择表及检查点回填随 V2 自动执行；旧库首次接入条件见 [数据库说明](../../backend/src/main/resources/db/README.md)。标准发布会先停掉旧后端并自动备份，再启动新后端迁移；部署需要更新后端和驾驶舱。本地离线测试不能证明生产 MySQL 锁、真实行情或实盘效果。
